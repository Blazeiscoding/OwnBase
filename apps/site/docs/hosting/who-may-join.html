Who may join

A workspace has one rule for who may join it: invite_only (people with an invite), account_required (anyone who creates an account) or guest_allowed (anyone, guests included). Its owner and administrators choose it in Workspace settings → Who can join, opened from the workspace menu, where it is saved the moment it is chosen and everyone signed in sees the change. The same page renames the workspace. Members and guests do not see it.

--access-policy (or --invite-only, which is --access-policy invite_only) and --name set up a workspace nobody owns yet. Once someone has claimed it, the workspace keeps its own name and rule, and a later start does not change either: a flag that disagrees is left alone, and the server prints a line saying the workspace keeps its own and where to change it.

Changed in this version: --access-policy and --invite-only used to be applied on every start, so a service or compose file that passed them put the rule back at each restart. They now apply to a new workspace only. To change the rule of a running workspace, use Workspace settings; a restart keeps it.

In the desktop app that hosts a workspace, Open to all in Manage hosting sets the rule chosen beside it for the public link. While the link is open, Manage hosting shows the workspace's rule and can change it, and a change made in Workspace settings shows there at once. One start still changes the rule: while a stable public address is configured, every start closes joining to invited accounts.
